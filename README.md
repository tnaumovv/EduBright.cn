# EduBright — образование в Китае

Адаптивный сайт для образовательного сервиса EduBright, который помогает абитуриентам выбрать программу обучения в Китае и подготовиться к поступлению. Посетитель может изучить направления обучения, познакомиться с этапами сопровождения и оставить заявку на консультацию. Заявка передаётся команде через Telegram.

Проект объединяет интерфейс на React, интерактивные компоненты, анимации и серверную интеграцию с Telegram Bot API.

**Стек:** React 18 · Vite 6 · JavaScript / TypeScript · CSS / Tailwind CSS 4 · Radix UI · Motion · React Hook Form · Vercel Functions

## Возможности

- **Направления обучения:** китайский язык, подготовка к HSK и бакалавриат в Китае. Для каждого направления открывается модальное окно с описанием и переходом к консультации.
- **Университеты и жизнь в Китае:** анимированная лента логотипов вузов и фотогалерея из восьми карточек.
- **Этапы сопровождения:** вкладки с информацией о поступлении, языковой подготовке, документах и адаптации.
- **История студента:** карточка с результатом поступления. Компонент поддерживает несколько историй, переключение кнопками и стрелками клавиатуры; сейчас на странице показан один кейс.
- **FAQ:** четыре категории вопросов с раскрывающимися ответами.
- **Форма консультации:** проверка обязательных полей, состояние отправки, подтверждение успеха и сообщения об ошибках. Во время запроса кнопка отправки блокируется.
- **Навигация:** якорные ссылки, подсветка текущего раздела, компактная шапка при прокрутке и отдельное мобильное меню.
- **Адаптивность и доступность:** разметка для разных размеров экрана, видимый фокус, ссылка для перехода к основному содержимому и учёт настройки уменьшения анимации.

## Технические решения

### Компонентная архитектура

Страница собрана из самостоятельных секций. Общие элементы — кнопки, анимации появления, форма и диалог программы — вынесены в переиспользуемые компоненты. Описания программ, этапов и FAQ хранятся отдельно от разметки в `src/data/content.js`.

Логика навигации и прокрутки мобильных вкладок выделена в хуки. Обновление состояния шапки при прокрутке выполняется через `requestAnimationFrame`.

### Отправка заявки через сервер

Браузер отправляет данные на собственный endpoint `POST /api/consultation`. Сервер повторно проверяет поля, ограничивает длину текста, экранирует HTML и вызывает Telegram Bot API. Токен бота и идентификатор чата читаются из серверных переменных окружения.

Интерфейс показывает успешную отправку только после ответа с `success: true`. При ошибке введённые данные сохраняются для повторной попытки; после успеха форма очищается.

### Доступность и анимации

Для диалогов, вкладок и FAQ используются примитивы Radix UI. Поля формы имеют подписи и связь с сообщениями об ошибках через ARIA-атрибуты. После выбора «Обсудить программу» диалог закрывается, страница прокручивается к форме, а фокус переходит на поле имени.

Анимации учитывают `prefers-reduced-motion`. Движение лент приостанавливается при наведении и фокусе; повторяющиеся элементы скрыты от скринридеров. Изображения и шрифты размещены локально, для многих изображений используется отложенная загрузка.

### Постепенное использование TypeScript

TypeScript подключён к существующему проекту на JavaScript. Для TS/TSX включён строгий режим, настроен алиас `@/*` → `src/*`. Основные JSX-файлы остаются на JavaScript: `checkJs` выключен, поэтому проверка типов не охватывает всю кодовую базу.

## Быстрый запуск

Для работы используйте Node.js 22 или 24 и npm.

```bash
git clone https://github.com/tnaumovv/EduBright.cn.git
cd EduBright.cn
npm ci
npm run dev
```

Откройте адрес из терминала — по умолчанию `http://localhost:5173`.

Для просмотра интерфейса переменные окружения не нужны. `npm run dev` запускает только Vite: серверная функция из `api/` в этом режиме не обслуживается. Для проверки отправки заявки используйте локальный запуск через Vercel или развёрнутый проект.

## Настройка Telegram и локального API

1. Создайте Telegram-бота через BotFather и получите токен.
2. Добавьте бота в нужный чат или начните с ним диалог. Получите идентификатор чата, в который должны приходить заявки.
3. Создайте локальный файл настроек:

   ```bash
   cp .env.example .env.local
   ```

4. Замените значения в `.env.local`:

   ```dotenv
   BOT_TOKEN=your-telegram-bot-token
   CHAT_ID=your-telegram-chat-id
   ```

| Переменная | Назначение | Где используется |
| --- | --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота | Серверная функция |
| `CHAT_ID` | Идентификатор чата для получения заявок | Серверная функция |

Оба значения обязательны для отправки заявки. `.env.local` исключён из Git. Не добавляйте токен в переменные с префиксом `VITE_`, поскольку они доступны клиентскому коду.

Запустите интерфейс и функции в локальном окружении Vercel:

```bash
npx vercel dev
```

При первом запуске CLI может запросить вход в аккаунт и привязку к проекту. Откройте адрес, который покажет терминал. Если переменные уже настроены в окружении Development проекта Vercel, их можно загрузить командой `npx vercel env pull .env.local` вместо ручного заполнения.

Подробнее: [локальная разработка с Vercel CLI](https://vercel.com/docs/cli/dev), [работа с переменными окружения](https://vercel.com/docs/cli/env).

## API консультации

`POST /api/consultation` принимает JSON:

```json
{
  "name": "Иван Иванов",
  "phone": "+7 (700) 123-45-67",
  "email": "student@example.com",
  "message": "Хочу узнать о подготовке к HSK"
}
```

Поля `name`, `phone` и `email` обязательны. Поле `message` необязательно. Номер телефона проверяется по наличию минимум шести цифр, email — по базовому формату. Ограничения длины: имя — 120, телефон — 40, email — 160, сообщение — 2000 символов.

| Код ответа | Значение |
| --- | --- |
| `200` | Заявка передана в Telegram; ответ `{ "success": true }` |
| `400` | Обязательные поля не прошли проверку |
| `405` | Использован метод, отличный от POST |
| `500` | Не настроены серверные переменные или возникла ошибка отправки |

Ответ при ошибке содержит `success: false` и поле `error` с сообщением. Клиент показывает только предусмотренные сообщения; неизвестные детали заменяет общим текстом ошибки.

## Команды и проверки

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск интерфейса в режиме разработки |
| `npm run build` | Сборка фронтенда в `dist/` |
| `npm run preview` | Локальный просмотр собранного фронтенда |
| `npm run typecheck` | Проверка TypeScript без генерации файлов |
| `npm test` | Запуск модульных тестов |

Перед публикацией:

```bash
npm test
npm run typecheck
npm run build
```

В `src/lib/consultation.test.js` реализованы пять тестов: валидация контактов, контракт запроса, обязательное подтверждение успеха, обработка серверных сообщений, некорректных ответов и сетевых ошибок. Запросы в тестах подменяются, поэтому токен и обращение к Telegram не нужны.

Тесты проверяют клиентскую логику консультации. Проверку доставки сообщения через серверную функцию нужно выполнять отдельно в настроенном окружении. `npm run preview`, как и обычный запуск Vite, не запускает API.

## Развёртывание

Проект содержит конфигурацию для Vercel: frontend собирается Vite, а `api/consultation.js` обрабатывает заявки как серверная функция. Поддержка функций для Vite-проектов описана в [документации Vercel](https://vercel.com/docs/frameworks/frontend/vite).

1. Импортируйте Git-репозиторий в Vercel.
2. Выберите пресет **Vite** и корень репозитория в качестве Root Directory.
3. Проверьте параметры сборки: **Build Command** — `npm run build`, **Output Directory** — `dist`.
4. Добавьте `BOT_TOKEN` и `CHAT_ID` в **Project Settings → Environment Variables** для нужных окружений.
5. Выполните развёртывание и отправьте тестовую заявку с сайта. После изменения переменных окружения создайте новое развёртывание.

Маршруты в `vercel.json` направляют API-запросы к функциям, а остальные запросы после поиска статических файлов — к `index.html`.

При размещении только содержимого `dist/` на статическом хостинге интерфейс будет доступен, но для формы потребуется отдельно развернуть API и настроить путь `/api/consultation`.

## Работа с контентом

- **Программы, этапы сопровождения, FAQ и навигация:** `src/data/content.js`.
- **Фотографии городов и подписи:** `src/data/cities.json`.
- **Список университетов:** `src/components/sections/Universities.jsx`.
- **Истории студентов:** массив `students` в `src/components/sections/StudentStory.jsx`.
- **Изображения и шрифты:** `public/assets/`.
- **Метаданные страницы:** `index.html`.

Дополнительные сведения о типизированных UI-компонентах, алиасах и настройке Tailwind находятся в [UI-SETUP.md](./UI-SETUP.md). Источники части фотографий указаны в `src/data/cities.json`, источники логотипов — в `public/assets/universities/sources.json`; лицензии локальных шрифтов лежат рядом с файлами в `public/assets/fonts/`.

Текущий сценарий проекта — знакомство с услугами и отправка заявки. Данные заявок передаются напрямую в Telegram; база данных и личный кабинет в текущей реализации отсутствуют.
